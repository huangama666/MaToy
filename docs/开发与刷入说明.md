# MaToy 开发与刷入说明

这篇教程介绍我这次实际使用的开发方法。目标是拿到源码后，能够在 Mac 上编译固件和发送端，把程序刷进 AI Passport，开发 MaToy 的界面、桌面缩放、电台和监控功能。

本说明对应清理后的项目：当前音视频源码、构建脚本、配网工具及使用资源已集中存放。下面所有操作都在本项目根目录执行。源码构建产物使用 MaToy 名称，`firmware/` 中此前发布的镜像保留原文件名；Mac Bundle ID、协议和配对文件格式沿用原标识。

我建议先把本版本完整跑通，再按文中的代码入口修改一个功能。它同时包含板端 C 程序和 Mac Swift 应用，只克隆官方仓库的 main 分支，拿不到这里的定制功能。

## 第一步：确认我要开发哪一部分

我用的设备是 ESP32-C3 版 AI Passport。项目基线为 8 MB Flash、无 PSRAM、240×320 屏幕，三个实体按键，带麦克风和扬声器。硬件引脚以 `source/firmware/components/bsp/include/bsp_pins.h` 为准，业务开发不需要重新接线。

我把职责分成两端：

| 功能 | 开发板端负责 | Mac 端负责 |
| --- | --- | --- |
| 远程桌面 | 接图、显示、按键、板端录音播放 | 采集桌面、裁剪、发送画面、执行输入、传输音频 |
| 电台 | 联网、MP3 解码、音量和播放界面 | 不需要运行发送端 |
| 远程监控 | 预览、镜头和声音开关、按键对讲 | 摄像头、麦克风采集、接收板端语音 |

USB 用来刷机和首次配置。日常桌面、摄像头和对讲走局域网，开发板连接 2.4 GHz Wi-Fi，Mac 与它处在可互通的网络。

本教程的 Mac 部分面向 Apple 芯片，沿用这次 macOS 26 的构建环境。Windows 和 Linux 可以开发板端，但不能直接运行这里的 Mac 发送端。

我在 Codex 中开发时，会先说明硬件、两端职责、页面和按键，再让它改代码。例如，这段需求可以作为本项目的继续开发起点：

```text
请先阅读本工程 README.md、docs/开发与刷入说明.md，以及涉及的源码。
目标硬件是 ESP32-C3、8 MB Flash、无 PSRAM 的 AI Passport。
保留电台、远程桌面、远程监控三个入口和现有配对格式。
这次只把默认电台音量改成 35，说明改了哪个文件。
用 scripts/build-firmware.sh 构建并校验镜像，先不要刷机。
不要改引脚、分区表或清除已有网络设置。
```

我一次只交代一项具体改动。涉及实体体验时，我还会把“按哪个键、屏幕应显示什么、哪一端应听见声音”写进验收要求，避免只有代码生成、没有可观察的结果。

## 第二步：定位项目，认识目录

将仓库克隆或解压到**路径不含空格**的目录，例如：

```text
~/Documents/MaToy/
```

进入目录，并记住根目录变量。下文命令默认都在这个终端中执行：

```zsh
cd ~/Documents/MaToy
export TUTORIAL_ROOT="$PWD"
```

目录的用途如下：

```text
MaToy/
├── source/
│   ├── firmware/
│   │   ├── main/               页面、状态机、传输、电台、语音
│   │   ├── components/bsp/     屏幕、按键、音频等硬件适配
│   │   ├── assets/             开机图、电台目录、生成资源
│   │   ├── tools/              图片字库生成、固件校验
│   │   ├── sdkconfig.defaults  默认配置
│   │   ├── partitions.csv     分区表
│   │   └── dependencies.lock  组件版本锁
│   └── mac/
│       ├── Control.swift       桌面采集、裁剪、控制和服务集成
│       ├── Camera.swift        摄像头与监控音频生命周期
│       ├── Voice.swift         音频采集、播放及加密传输
│       └── Info.plist          应用身份和权限用途说明
├── scripts/                   两端构建脚本
├── tools/                     USB 配置与配对工具
├── assets/                    重新生成中文字库所需字体
├── firmware/                  已刷入版本及临时 Wi-Fi 配置固件
├── outputs/                   编译出来的 Mac 应用
├── build/                     本机生成的编译产物
└── work/                      本机配对文件，不随包分享
```

项目不再携带 ESP-IDF、编译器和下载组件缓存；本机配对文件单独保留在 work，分享时务必排除。首次重新准备环境后按依赖锁下载组件；已有生成好的图片和字库，初次编译无需重生成。

## 第三步：准备 ESP-IDF 与 Swift 环境

### 3.1 先检查工具

我在终端检查：

```zsh
uname -m
xcode-select -p
xcrun swiftc --version
command -v brew
```

缺少 Xcode Command Line Tools 时运行 `xcode-select --install`，按系统提示安装。Homebrew 需要先按其官方方式安装；已经有的工具不用重复安装。

板端构建所需工具可通过 Homebrew 准备：

```zsh
brew install cmake ninja ccache dfu-util libusb python@3.12
```

这些命令会安装本机开发工具。为了与这次环境保持一致，我使用 Python 3.12 和 ESP-IDF **v5.5.3**。

### 3.2 安装或激活固定版本 ESP-IDF

如果本机已经有 v5.5.3，我直接激活它；否则单独安装，不覆盖其他版本：

```zsh
export AI_PASSPORT_IDF_ROOT="$HOME/esp/esp-idf-v5.5.3"
mkdir -p "$(dirname "$AI_PASSPORT_IDF_ROOT")"
git clone --branch v5.5.3 --recursive \
  https://github.com/espressif/esp-idf.git \
  "$AI_PASSPORT_IDF_ROOT"

# 只在当前终端优先使用 Homebrew 的 Python 3.12。
export PATH="$(brew --prefix python@3.12)/libexec/bin:$PATH"
"$AI_PASSPORT_IDF_ROOT/install.sh" esp32c3
source "$AI_PASSPORT_IDF_ROOT/export.sh"
idf.py --version
```

最后一行应显示 `ESP-IDF v5.5.3`。若安装目录已存在，就先检查版本并执行 `source`，不要再次向同一个目录 clone。工具链安装、`install.sh esp32c3` 和环境激活步骤可对照 [Espressif v5.5.3 官方安装指南](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/get-started/linux-macos-setup.html)。

我每次开新终端，都需要重新设置 `AI_PASSPORT_IDF_ROOT`、执行 `source`，并回到项目根目录。找不到 `idf.py` 往往只是环境还没激活。

### 3.3 准备 USB 工具

在项目根目录单独创建工具虚拟环境：

```zsh
cd "$TUTORIAL_ROOT"
python3 -m venv .venv
PY="$TUTORIAL_ROOT/.venv/bin/python"
"$PY" -m pip install -r tools/requirements.txt
```

`tools/接入.py` 用 pyserial 配置设备，esptool 用来刷机。这里不用 `source .venv/bin/activate`，避免把已激活的 ESP-IDF Python 环境切走；需要 USB 工具时直接调用 `"$PY"`。

## 第四步：先从源码编译，不急着改功能

我先运行板端构建脚本：

```zsh
cd "$TUTORIAL_ROOT"
bash scripts/build-firmware.sh
```

脚本会检查 ESP-IDF 版本，根据依赖锁解析组件，在 `build/firmware` 生成配置和构建产物，然后合并、校验完整镜像。首次下载组件时需要联网。

主要产物是：

```text
build/firmware/MaToy.bin       应用镜像
build/firmware/MaToy-full.bin  完整布局镜像
build/firmware/MaToy.elf       调试信息
build/firmware/partition_table/partition-table.bin
```

脚本里的核心命令如下。实际使用时运行脚本即可，不必再重复执行这一组：

```zsh
cd "$TUTORIAL_ROOT/source/firmware"
SDKCONFIG_DEFAULTS="$PWD/sdkconfig.defaults" \
  idf.py -B "$TUTORIAL_ROOT/build/firmware" \
  -D "SDKCONFIG=$TUTORIAL_ROOT/build/firmware/sdkconfig" build
idf.py -B "$TUTORIAL_ROOT/build/firmware" merge-bin \
  -o "$TUTORIAL_ROOT/build/firmware/MaToy-full.bin"
python3 tools/verify_firmware.py "$TUTORIAL_ROOT/build/firmware"
cd "$TUTORIAL_ROOT"
```

Mac 端使用另一份脚本：

```zsh
bash scripts/build-mac.sh
```

它编译三份 Swift 文件、复制 Info.plist 并进行本机临时签名，输出：

```text
outputs/MaToy.app
```

脚本不会自动打开应用，也不会替我申请系统权限。此时我先确认两端都编译成功，再进入配置和刷机步骤。**编译成功只能证明构建通过，不能证明麦克风、按键或摄像头在真机上正常。**

如果要直接了解 Mac 的构建命令，脚本执行的关键步骤就是：

```zsh
APP="$TUTORIAL_ROOT/outputs/MaToy.app"
mkdir -p "$APP/Contents/MacOS" "$TUTORIAL_ROOT/build/ModuleCache"
cp source/mac/Info.plist "$APP/Contents/Info.plist"
swiftc -module-cache-path "$TUTORIAL_ROOT/build/ModuleCache" \
  -parse-as-library -O \
  source/mac/Control.swift source/mac/Voice.swift source/mac/Camera.swift \
  -o "$APP/Contents/MacOS/PassportControl"
codesign --force --sign - "$APP"
codesign --verify --strict --verbose=2 "$APP"
```

我没有额外引入 Swift 第三方包，这些 Swift 文件使用 macOS SDK 的框架。Info.plist 中保留摄像头、麦克风及本地网络的用途说明；只复制可执行文件，不能替代完整应用包。

## 第五步：理解板端入口，再动界面

我从 `source/firmware/main/CMakeLists.txt` 看起。本版真正参与应用编译的源文件是：

```cmake
idf_component_register(
    SRCS "screen_app.c" "voice_link.c" "radio_player.c" "radio_ui.c"
    INCLUDE_DIRS "."
    EMBED_FILES
        "../assets/images/live_control_standby.rgb565"
        "../assets/images/live_control_standby_portrait.rgb565"
    REQUIRES bsp esp_event esp_netif esp_wifi
        esp_driver_usb_serial_jtag esp_hw_support
        esp_http_client mbedtls nvs_flash)
```

`main` 仅保留当前应用实际使用的四份 C 实现、头文件和组件配置。运行入口为 `screen_app.c` 中的 `app_main()`；上游硬件演示页面已移除。

本版入口按以下顺序初始化：NVS → USB 配置任务 → 屏幕 → 按键队列 → 开机图 → 网络、电台与语音 → 页面主循环。

首页和电台的状态定义在 `main/launcher_state.h`：

```c
typedef enum { PAGE_HOME, PAGE_RADIO, PAGE_REMOTE, PAGE_MONITOR } launcher_page_t;
```

上下键在三个首页选项间循环，确定键把 `launcher.page` 改为目标页面。主循环检测到页面变化后，再负责停旧任务、切换屏幕方向和启动新功能。

我把界面代码留在 `main`，引脚和硬件驱动留在 `components/bsp`。例如，修改首页文案不需要改 SPI 引脚，修改电台音量也不需要重写音频驱动。

本版定制页面直接使用图像块与像素绘制；不要把它误认为通过修改几个 LVGL label 就能改完所有界面。如果另建 LVGL 页面，需要遵守 BSP 的 LVGL 锁规则。

## 第六步：实现横竖屏与三键操作

我让首页、电台和监控使用 240×320 竖屏，桌面使用 320×240 横屏。相关入口是 `screen_app.c` 的 `set_portrait()`，页面切换时调用：

```c
set_portrait(launcher.page != PAGE_REMOTE);
```

这里复用 BSP 返回的 LCD panel，再通过面板的交换坐标轴和镜像参数控制方向。换屏或出现左右反转时，应检查这个函数和 `bsp_pins.h`，不要同时改网络图像坐标、按键方向和屏幕驱动来碰运气。

三个按键的业务分派分两层：BSP 识别按下、松开、单击、双击、三击、长按；应用根据当前页面解释事件。我的 BSP 快照包含三连按支持，所以不能只复制 `screen_app.c` 到未改造的上游 BSP。

桌面模式的主要操作是：

| 操作 | 行为 |
| --- | --- |
| 短按上下键 | 沿当前轴移动鼠标 |
| 长按确定 | 切换横向和纵向移动 |
| 短按确定 | 单击 |
| 双按确定 | 屏幕键盘开关 |
| 三连按确定 | 全桌面与原放大视图切换 |
| 长按上键 | 打开右上角分类菜单 |
| 按住下键 | 麦克风对讲，松开恢复接收 |

菜单分类在 `main/screen_menu.h`，菜单事件在 `screen_app.c` 的 `poll_input()` 中处理。键盘模式另行处理字符组、数字、Enter 和退格。

开发时我特别注意：按键回调只处理轻量状态、事件投递和对讲按下/松开信号，网络连接、解码和设备采集放到循环或工作任务里。切页面时还要清掉旧队列，避免前一页的按键落到后一页。

## 第七步：开发 Mac 桌面采集和跟随放大

Mac 端我先看 `source/mac/Control.swift`，按这个顺序阅读：

1. `CapturedScreen.render`：裁剪和 RGB565 输出。
2. `FrameStore`：当前帧与显示模式。
3. `Capture`：接收 ScreenCaptureKit 回调。
4. `ScreenServer`：握手、图像发送、控制消息。
5. `MirrorApp`：菜单、权限、服务启动。

采集链路是：

```text
主显示器 → SCStream → CVPixelBuffer
  → 按鼠标位置裁剪 → 缩放 → RGB565
  → 分带加密 → TCP → 开发板解密显示
```

“跟随鼠标放大”发生在发送端的源图裁剪中，不修改 Mac 系统缩放。当前显示模式定义如下：

```swift
enum ViewMode: Int, CaseIterable {
    case text = 6
    case follow = 3
    case full = 1
}
```

`render` 先计算 `sourceWidth / zoom` 和 `sourceHeight / zoom`，再围绕鼠标计算裁剪边界。这里必须先从较高清的源图裁剪，再缩到板端尺寸；先缩小整张桌面再放大，会把已经丢掉的字形细节一起放大。

**我的第一个改造练习：把 6 倍文字模式改成 4 倍。**

我把 `case text = 6` 改成 `case text = 4`，同时把该枚举 `title` 里的“6 倍”改为“4 倍”，再运行 `bash scripts/build-mac.sh`。捕获配置使用该枚举的倍率值，板端仍接收相同尺寸的图像，所以这个练习只需要更新 Mac 端，不需要改网络协议或刷板。

要让新版本生效，先退出正在运行的旧应用，再打开新应用；macOS 可能要求重新授予屏幕录制权限。项目初始代码仍保留本次实际使用的 6 倍值，我没有预先替读者执行这个练习。

## 第八步：把输入变成 Mac 鼠标与键盘事件

板端发送的是控制消息，不直接把物理按钮映射为 Mac 的某个 GPIO。桌面控制消息的主要类型为：

| kind | 含义 |
| --- | --- |
| 1 | 鼠标移动，value 打包 16 位归一化 x、y |
| 2 | 指定位置鼠标单击 |
| 3 | 字符或特殊按键 |
| 4 | 全桌面视图切换 |

Mac 解密并校验消息后，进入 `ScreenServer.sendMacInput()`。鼠标坐标按当前主显示器边界换算，再用 `CGEvent` 投递；Enter、Tab、退格走特殊键码，普通字符使用 Unicode 字符输入。

执行输入前要检查 `AXIsProcessTrusted()`。没有辅助功能权限时，“能看到画面但不能控制”是可以出现的状态。继续调图像采集参数不会修好这个问题。

## 第九步：按图像带设计传输

为了控制板端内存，我没有为网络收图长期保留额外的整帧缓冲。RGB565 每像素两字节，一个 320×240 全帧约 150 KiB；一个 320×8 的图像带约 5 KiB。

`Control.swift` 的 `sendFrame()` 每次最多发送 8 行。每条记录包含：

```text
width:uint16 | height:uint16 | y:uint16 | rows:uint16 | sequence:uint32
密文：width × rows × 2 字节 RGB565
GCM tag：16 字节
```

整数按大端序序列化，Mac 的 `Data.put` 与板端解码保持一致。图像头作为 AES-GCM 的附加认证数据；序号参与 nonce 和顺序校验。修改记录格式时，Mac 和板端应一起改，不能只在其中一端加字段。

板端 `screen_app.c` 中的 `pixels`、`decoded`、`ciphertext` 分别承担绘制、解密后像素和密文缓冲。**单块约 5 KiB 不等于整个应用只用 5 KiB RAM。** 显示完成通知用于保证 DMA 尚未结束时不复用缓冲。

桌面使用 `APSC2` 握手标识，摄像头使用 `APCM2`。USB 配对保存的密钥参与挑战应答和会话密钥派生。实现采用现有 CryptoKit 与 mbedTLS API，教程不让读者自行换成无认证明文控制。

## 第十步：开发网络电台

电台主要看四组文件：

- `radio_player.c/.h`：HTTP 流、MP3 解码、PCM 输出、音量与状态。
- `radio_ui.c/.h`：频道信息、音量和动态指示绘制。
- `launcher_state.h`：切台、暂停、地区选择和音量页。
- `assets/radio/stations.json` 与 `radio_catalog.h`：目录原始数据和生成结果。

我让网络读取和解码跑在工作任务里。页面通过 `radio_player_select()` 和 `radio_player_volume()` 发送意图，通过状态和 telemetry 读取播放进度、采样率及指示值。

短按上下键切台，短按确定暂停；长按上/下键调整音量，每次 5，范围 0～90。电台和语音使用同一把 `audio_owner` 互斥锁，避免同时占音频硬件。

**我的第二个改造练习：改变默认音量。**

在 `main/launcher_state.h` 中把：

```c
#define LAUNCHER_INITIAL_STATE {.page = PAGE_HOME, .volume = 55, .channel = RADIO_DEFAULT_STATION}
```

里的 `.volume = 55` 改成 `.volume = 35`，重新编译并只刷应用分区。这个改动影响板端启动状态，不需要重编译 Mac 应用。

修改频道目录时，我编辑 JSON 后运行：

```zsh
python3 source/firmware/tools/generate_radio_catalog.py source/firmware
```

当前生成器要求频道 ID 唯一、地区的 `first/count` 连续覆盖所有频道，且默认频道 ID 266 存在。删掉默认台时，要同步改生成器中的默认 ID。当前播放 URL 根据频道 ID 生成，随意加入一种其他网站的完整 URL 不会自动获得支持；增加新源类型需要修改 `radio_player.c`。

公开广播源是否可用要单独检查，不能把目录生成成功当成播放成功。

## 第十一步：开发可开关的摄像头监控

监控复用图像发送、加密和分带显示机制。Mac 增加 `Camera.swift`，板端增加 `PAGE_MONITOR` 和 `receive_monitor()`，图像端口改为 TCP 45904。

我在 `Camera.swift` 中用 `AVCaptureSession` 采集摄像头，把结果存进 `FrameStore(cursorEnabled: false)`，因此摄像头画面不叠加桌面鼠标。

板端监控控制消息沿用加密输入格式，增加：

```text
kind=5，value=0/1：关闭/开启摄像头
kind=6，value=0/1/2：关闭声音/环境音监听/语音对讲
```

Mac 的监控服务只接受这些监控消息，不把它们转成鼠标键盘事件。每次新进入监控，板端请求镜头开启、声音关闭；六个操作按钮位于竖屏预览下方。

我还发送无像素负载的状态记录：width 为 0，height 字段承载状态码，并保留认证标签。镜头状态为 0～6，音频状态为 16 加对应状态值。板端据此显示授权等待、开启中、已关闭或失败。

开发时最容易漏的是没有画面时的按键处理。我通过接收等待钩子继续处理关闭和返回操作，避免摄像头关闭后页面被网络接收卡住。

另一个重点是异步权限回调。`Camera.swift` 使用会话 lease，音频使用 revision：如果我已经退出监控或按了关闭，稍后才返回的授权回调会因身份或版本过期而被丢弃，不能重新打开采集。

## 第十二步：加上监听和按键对讲

音频路径在 Mac 的 `Voice.swift` 与板端的 `voice_link.c`。桌面语音走 TCP 45903，监控语音走 TCP 45905，切换功能时板端切换目标端口并结束旧会话。

传输音频统一为 16 kHz、单声道、16 位 PCM。20 ms 为一块，即 320 个采样、640 字节。源音频不满足格式时，在 Mac 端转换后再进入传输队列。

我把监控的模式定义为：

| 模式 | 行为 |
| --- | --- |
| 0 | 关闭监控音频 |
| 1 | Mac 麦克风 → 开发板，监听环境声音 |
| 2 | 继续监听，并允许按住下键把板端声音传到 Mac |

按下/松开处理在板端 `on_button()` 和 `voice_push_to_talk()`。模式 2 中，按住下键开始讲话，松开恢复接收；模式 1 不启用上行讲话。

这版是按键式轮流对讲。若要改成免提全双工，还需要处理声学回声消除、输入输出同步和更复杂的缓冲策略，不能只把“按住”判断删掉。

## 第十三步：修改开机图片和中文文字

本版使用配套的 `live_control_standby.png` 生成横、竖两份 RGB565 资源，竖屏图上下留白，保持正方形插画比例。原生成脚本要求输入图为 **940×940**。

我在根目录创建素材工具环境：

```zsh
python3 -m venv .assets-venv
ASSET_PY="$TUTORIAL_ROOT/.assets-venv/bin/python"
"$ASSET_PY" -m pip install Pillow fonttools

"$ASSET_PY" source/firmware/tools/generate_launcher_assets.py \
  source/firmware/assets/images/live_control_standby.png \
  assets/NotoSerifSC-Var.ttf source/firmware

"$ASSET_PY" source/firmware/tools/generate_radio_font.py \
  source/firmware assets/NotoSerifSC-Var.ttf
```

换图时先把自己的图准备成 940×940，再替换 PNG 并重新生成。不想固定这个尺寸，就先修改生成脚本的尺寸约束与排版逻辑。

新增中文文案时也要重新生成字库：第一个脚本生成菜单字形，第二个覆盖电台和相关界面文案、频道名称。UTF-8 字符串能编译，不代表屏幕字库包含新字。字体文件及 OFL 授权随教程包提供，字体本身不直接整份刷入设备，固件使用生成的字形子集。

完成资源修改后再次运行 `bash scripts/build-firmware.sh`，不要只改 PNG 后刷旧 bin。

## 第十四步：连接设备、写网络、刷入并配对

### 14.1 找到串口

让设备开机，用能传数据的 USB 线直连 Mac。在项目根目录执行：

```zsh
PY="$TUTORIAL_ROOT/.venv/bin/python"
"$PY" tools/接入.py port
```

工具要求识别到一台对应的 Espressif USB 设备。串口可能是 `/dev/cu.usbmodem1101`，但必须以实际检测为准。先关闭占用串口的监视工具。需要手动排查枚举时，可对照 [ESP32-C3 官方串口连接说明](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/get-started/establish-serial-connection.html)，在拔插前后比较 `ls /dev/cu.*` 的结果。

### 14.2 网络未配好时，先用临时配置固件

设备已保存可用 Wi-Fi 时跳过本段。下面的应用分区命令只适用于**已经采用本项目分区布局**的设备：

```zsh
PORT=$("$PY" tools/接入.py port) && test -n "$PORT" &&
  "$PY" -m esptool --chip esp32c3 --port "$PORT" --baud 460800 \
  --before default_reset --after hard_reset write_flash \
  --flash_mode dio --flash_freq 80m --flash_size 8MB \
  0x10000 firmware/AI-Passport-WiFi-Setup-app.bin

"$PY" tools/接入.py wifi
```

工具先问 Mac 的局域网 IPv4，可以回车采用检测值；随后才是 Wi-Fi 名称和密码，密码输入不回显。看到“Wi-Fi 已写入”再继续。

对于空白板或明确要重新初始化布局的设备，需要先使用完整配置镜像：

```zsh
PORT=$("$PY" tools/接入.py port) && test -n "$PORT" &&
  "$PY" -m esptool --chip esp32c3 --port "$PORT" --baud 460800 \
  --before default_reset --after hard_reset write_flash \
  --flash_mode dio --flash_freq 80m --flash_size 8MB \
  0x0 firmware/AI-Passport-WiFi-Setup-full.bin
```

完整镜像会覆盖原布局和相应存储范围，应按重新初始化处理。之后再运行 `wifi`。分区未知且需要保留原资料时，先核对布局，不能套用应用偏移地址。

### 14.3 刷自己刚编译的正式应用

```zsh
PORT=$("$PY" tools/接入.py port) && test -n "$PORT" &&
  "$PY" -m esptool --chip esp32c3 --port "$PORT" --baud 460800 \
  --before default_reset --after hard_reset write_flash \
  --flash_mode dio --flash_freq 80m --flash_size 8MB \
  0x10000 build/firmware/MaToy.bin
```

我这里刷的是本次构建输出，不是 `firmware/` 中附带的上一版文件。`0x10000` 是应用镜像地址，完整 `full.bin` 的起点才是 `0x0`，两者不能对调。

本项目分区表是 NVS `0x9000`、PHY `0xf000`、factory 应用 `0x10000`。在兼容布局上只刷应用，可保留此前写入的网络和配对；改变 NVS 格式或分区表则需要重新评估迁移方式。

### 14.4 USB 配对并打开应用

```zsh
"$PY" tools/接入.py pair
open "outputs/MaToy.app"
```

配对把 Mac 地址与随机密钥写入板端，同时生成 `work/mac-screen-pair.json`。应用按自身所在目录的上两级寻找 `work`，因此要保留 `outputs/应用` 与 `work/配对文件` 的相对位置。

同一台 Mac、地址未变且已有正确配对文件时可以复用，不必每次刷应用都重新配对。分享源码或打包时不要附带该文件。

## 第十五步：授予系统权限，逐项验收

我在 macOS「系统设置 → 隐私与安全性」给当前构建的「MaToy」授予：

| 权限 | 对应功能 |
| --- | --- |
| 屏幕与系统音频录制 | 桌面画面、系统声音 |
| 辅助功能 | 鼠标和键盘控制 |
| 摄像头 | 监控图像 |
| 麦克风 | 环境声音与对讲 |

如果系统询问本地网络，也要允许。按系统提示退出并重新打开应用，随后按下列顺序检查：

1. 开机图之后进入纯色三项首页，而不是自动进入桌面。
2. 进入电台，切台、暂停、调整音量，确认实际扬声器输出。
3. 进入桌面，确认是当前会话；测试横纵鼠标移动、单击、键盘数字、Enter 和退格。
4. 三连按确定，检查全桌面和局部放大切换；确认 Mac 自身缩放未改变。
5. 进入监控，检查摄像头预览；关闭镜头后预览清空，再开启。
6. 选开启声音，对 Mac 麦克风讲话，确认板上听见；关闭声音后确认停止。
7. 选语音对讲，按住下键对板端讲话，确认 Mac 听见，松开再检查接收。
8. 返回首页，确认监控会话停止采集；重进监控确认声音默认关闭。

我不会用“编译通过”替代这一组检查，也不会用程序发送的合成音频替代物理麦克风听感。

## 遇到问题时，我从哪一层查

| 现象 | 我先检查什么 |
| --- | --- |
| `idf.py` 不存在 | 是否在当前终端激活 v5.5.3 |
| 临时配网工程提示无法用 `git describe` 获取版本 | 配网源码未带 Git 元数据，该提示本身不等于构建失败；继续看最终构建和布局校验结果 |
| 下载组件失败 | 网络、组件注册表、依赖锁；不关闭 TLS 校验 |
| 找不到串口 | 设备开机、数据线、USB 枚举、串口占用 |
| 首页有中文空白 | 是否重新生成字库、实际使用哪个字库 |
| 有桌面无控制 | 辅助功能权限及控制消息 |
| 摄像头有图，桌面没图 | 屏幕录制权限独立检查 |
| 只能听 Mac | 是否在对讲模式、是否按住下键、上行是否有数据 |
| 摄像头关闭后返回键失效 | 无帧等待期间是否继续处理按键 |
| 换网络后连不上 | Mac 地址变化、两端是否能互通、重新配对 |

检查 Mac 端口与日志可用：

```zsh
lsof -nP -iTCP:45902 -iTCP:45903 -iTCP:45904 -iTCP:45905
/usr/bin/log show --last 5m --style compact \
  --predicate 'process == "PassportControl" AND subsystem == "local.ai-passport.live-control"'
```

板端启动与重连问题，可以在已激活 ESP-IDF 的终端查看串口日志：

```zsh
PORT=$("$PY" tools/接入.py port)
idf.py -C "$TUTORIAL_ROOT/source/firmware" \
  -B "$TUTORIAL_ROOT/build/firmware" -p "$PORT" monitor
```

用 Ctrl+] 退出串口监视，再运行配对或刷机命令，避免串口被占用。

某个新版本签名变化后，设置页里的旧屏幕录制记录可能没有对应到当前进程。确认日志指向该问题时，我先退出应用，只重置它的屏幕录制记录：

```zsh
tccutil reset ScreenCapture local.ai-passport.live-control
open "outputs/MaToy.app"
```

然后在系统界面重新允许并按提示重开；这个命令本身不授予权限。我不把清空全部隐私权限当成常规修复步骤。

## 我怎样继续迭代这个工程

每次我先确定改动属于哪一端：改桌面裁剪通常只重编 Mac；改首页、按键、电台和板端显示要重新刷应用；改协议字段则两端都要更新。

初学时，我会依次做三个小改动：先把默认音量改成 35，再把文字模式倍率改成 4，最后换开机图并生成资源。每次只改一项，完成构建和对应真机检查，再继续加功能。这样一旦失败，我知道该回到哪个文件和哪条链路排查。
